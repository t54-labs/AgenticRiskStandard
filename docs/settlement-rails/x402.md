# x402 Payment Rail

x402 is the payment rail used by the AP2 concrete implementation. It enables gasless USDC transfers on EVM-compatible chains using EIP-3009 `transferWithAuthorization`. The user signs a transfer authorization offline, and a Coinbase facilitator submits it on-chain.

## How x402 Works

In a traditional on-chain transfer, the sender must hold the native gas token (ETH) to pay transaction fees. EIP-3009 allows a different model: the sender signs an off-chain authorization, and a third party (the facilitator) submits it on-chain and pays the gas. The sender only needs USDC, not ETH.

The x402 protocol wraps this into a standard flow:

1. **Create payment requirement**: The server generates a `PaymentRequirement` specifying the network, asset (USDC address), amount, recipient, and timeout.
2. **Verify**: The payment payload from the client is verified against the requirement.
3. **Settle**: The facilitator submits the signed authorization on-chain, transferring USDC from sender to recipient.

## X402Settlement ABC

```python
class X402Settlement(ABC):
    async def create_payment_requirement(self, job_id, amount, currency) -> PaymentRequirement
    async def verify(self, job_id, payment_payload, payment_requirement) -> VerifyResult
    async def settle(self, job_id, payment_payload, payment_requirement) -> SettleResult
```

This is an x402-specific abstraction, not a general payment rail interface. It lives in `src/ap2/server/x402.py` because it is AP2-specific.

## LiveX402Settlement

The live implementation uses the Coinbase x402 SDK:

```python
x402 = LiveX402Settlement(
    facilitator_url="https://api.developer.coinbase.com/x402/facilitator",
    pay_to="<escrow-contract-address>",
    network="eip155:8453",  # Base Mainnet
)
```

It supports Base Mainnet (`eip155:8453`), Base Sepolia (`eip155:84532`), and Ethereum Mainnet (`eip155:1`). USDC contract addresses are hardcoded for each network.

## MockX402Settlement

The mock implementation returns deterministic transaction hashes and network identifiers for testing. It tracks verified jobs to ensure `settle` is only called after `verify`.

## Role in the Settlement Stack

x402 is not the settlement layer. It is the **payment rail** that the settlement layer uses internally. The `LiveSettlementLayer` composes x402 with the escrow contract:

1. x402 transfers USDC from the user's wallet into the escrow contract.
2. The escrow contract tags the deposit (fee, collateral, or principal).
3. Later, the escrow contract releases, refunds, or slashes the deposit based on protocol outcomes.

x402 handles the "how do funds get into escrow" question. The escrow contract handles the "where do funds go after escrow" question.
